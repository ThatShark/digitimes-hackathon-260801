## 一、問題定義

### 我們要解決什麼問題？

現有的加密貨幣投資工具有一個共同的盲點：**它們只看市場，不看你這個人。**

市面上的工具（Bitsgap、Token Metrics 等）給所有人一樣的分析報告、一樣的買賣訊號。但兩個人面對同樣的市場，應該做出不同的決定——因為他們的風險承受度、過去的交易習慣、資金分配方式都不一樣。

### 目標使用者

> **「每天都在交易、但從來沒有時間好好了解自己在幹嘛的加密貨幣投資人。」**
> 

具體特徵：

- 在 MAX 交易所每天有多筆交易
- 同時持有多種幣種（BTC、ETH、SOL 等）
- 憑感覺或習慣進出場，沒有系統化分析自己的決策
- 沒有時間整合市場資訊、鏈上數據、新聞情緒

### 現有工具的缺口

| 競品能做 | 競品做不到 |
| --- | --- |
| 市場走勢分析 | 分析「你這個人」的交易習慣 |
| 買賣訊號 | 根據你的個人風格調整建議 |
| 自動下單 | 告訴你過去哪筆交易做錯了、為什麼 |
| K 線圖表 | 讓你對自己的投資行為產生情感連結 |

### 品牌方命題需求

在今日 ( 7 / 15 ) 的品牌方講解題目流程時，講師有提及以下事項

- 多維度互動式介面：不限於傳統 Dashboard，可開發動態外連、實時數據視覺化（Data Visualization）或高度客製化一個投資人需要或想要的儀表板。（創意分數為最高 25%）
- 智慧 AI 數據分析：串聯 AWS AI 服務，打造能主動解讀市場情緒、預測趨勢並回答複雜投資問題的「AI 投資特助」。
- 對話式下單生態：整合 MAX 交易所的 API 與 Skill，實現 「提問－＞AI 策略分析－＞自動調用 Skill 串接 MAX 交易所下單」的一鍵式閉環交易流程。

因此，接下來的設計除了現有工具缺口，會在 UI 界面做出一些「創新」要素

**智慧投資 L. I. V. E.**

### 一句話定位

### 兩大核心亮點

#### 亮點一：投資人人格系統（類 MBTI）

AI 讀取使用者的 CSV 交易紀錄，分析出這個人的「投資人人格」，並在整個產品中根據人格客製化建議。

四種人格類型：

| 人格 | 特徵 | 行為模式 |
| --- | --- | --- |
| 🦁 熱衷型投資人 | 高頻交易、短期持倉 | 常在市場恐慌時錯誤賣出 |
| 🐢 安逸型投資人 | 大量持有穩定幣、低頻交易 | 很少虧但也錯失大漲 |
| 🦊 保守型投資人 | 選擇性出手、等待條件 | 勝率高但進場次數少 |
| 🎲 冒險型賭徒（渾沌） | 大單集中在單一幣種 | 爆賺或爆虧，波動大 |

人格不是二元的，AI 會說：「你主要是熱衷型投資人，但你對 BTC 的操作顯示有安逸型的一面。」

人格參考：

- https://av.sc.com/tw/edm/2020/September/edm-20200908/index.html
- https://www.esunsec.com.tw/article/post/7

#### 亮點二：YouTube 直播風格 UI

把每個幣種做成一個「直播頻道」：

- **主頁面**：像 YouTube 首頁，有多個直播縮圖，每個對應一個幣種
- **直播頁面**：K 線圖當「直播畫面」，AI 對話框當「聊天室」
- AI 扮演一個有個性的虛擬主播，根據使用者人格給出個人化建議

市場上完全沒有這樣的投資工具，評審第一眼就會記住。

#### 備案功能：Brilliant / Blunder 投資覆盤系統（類 chess.com）

> ⚠️ 此功能列為備案，有時間再做。
> 

AI 自動找出使用者歷史上最好和最糟的交易，疊加在 K 線圖上，點擊後 AI 用人話解釋原因。

**💥 Blunder 範例：**

> 你在 2025/04/13 以 11,200 TWD 賣出 ETH
當天恐懼貪婪指數為 22（極度恐慌），這通常是買入而非賣出的訊號
三天後 ETH 漲至 13,800 TWD — 這筆交易讓你少賺了約 NT$8,400
> 

**✨ Brilliant 範例：**

> 你在 2025/07/02 買入 SOL
當天鏈上活躍地址數創 30 天新高，大盤情緒剛從恐慌轉為中性
你比多數人早 5 天進場，最終獲利 31%
>

### 功能一：人格分析

#### 整體流程

```
CSV 10,000 筆
    ↓ Python 計算指標（Lambda）
結構化指標數據
    ↓ 送給 AWS Bedrock Claude
AI 判斷人格類型並產生描述
```

> 原則：讓 Python 做數學，讓 AI 做解讀。
> 

#### 計算指標

整體層面（全部幣種合在一起算）：

- **交易頻率**：每天平均幾筆交易
- **穩定幣佔比**：USDT、USDC 佔總資產的比例

幣種層面（BTC、ETH、SOL、DOGE 各算一次）：

- **追漲率**：買入前 N 天漲幅相對於該幣種正常波動的比例（相對波動度）
- **平均停損幅度**：虧損賣出時，平均虧損幾%才賣
- **平均持倉天數**：買入到賣出之間平均幾天
- **平均收益**：每筆交易的平均損益%
- **收益標準差**：每筆交易損益的標準差（衡量策略穩定度）

幣種層面算完後可以額外得出：

- 使用者偏好交易哪種幣
- 他對不同幣種的策略是否一致

#### 人格判定邏輯

**第一組：衝動型 vs 防禦型**

| 指標 | 衝動型 | 防禦型 |
| --- | --- | --- |
| 交易頻率 | 高 | 低 |
| 穩定幣佔比 | 低 | 高 |
| 追漲率 | 高 | 低 |
| 平均停損幅度 | 小跌就跑 | 撐很久才賣 |
| 平均持倉天數 | 短 | 長 |

**第二組：有計劃 vs 亂來**

| 平均收益 | 收益標準差 | 判定 |
| --- | --- | --- |
| 正 | 小 | 有計劃，策略穩定 |
| 正 | 大 | 運氣好的賭徒 |
| 負 | 小 | 策略有問題但很一致 |
| 負 | 大 | 亂來，冒險型賭徒 |

**跨幣種行為一致性：**

- **一致**：進一步看是有計劃還是亂來
- **不一致且收益穩定**：保守型投資人
- **不一致且收益不穩定**：冒險型賭徒

#### AI 輸出內容

把所有指標送給 Bedrock Claude，讓 AI 回答三件事：

1. **主要人格**
2. **次要人格**（跨幣種行為不一致時才有）
3. **人話描述**：用自然語言描述這個人的投資風格

#### 流程圖

```
開始
↓
S3 是否已有人格資料？
├── 是 → 直接讀取人格資料 → 回傳給前端 → 結束
└── 否 ↓
從 S3 讀取 CSV
↓
CSV 存在且格式正確？
├── 否 → 要求使用者上傳 CSV → 回到讀取
└── 是 ↓
計算整體層面指標
↓
計算幣種層面指標
↓
輸出成 JSON
↓
送給 Bedrock AI
↓
AI 有回應？
├── 否 → 重試（最多 3 次）
│         超過 3 次 → 回傳錯誤畫面給前端 → 結束
└── 是 ↓
AI 產生人格描述
↓
將結果存回 S3
↓
回傳給前端
↓
結束
```

#### 待討論

- 各指標的具體門檻值（例如持倉幾天以上算長線？）
- 追漲率的相對波動度計算方式
- AI Prompt 要怎麼寫

### 功能三：AI 對話下單

#### 完整流程

```
使用者輸入：「我想買 ETH」
        ↓
AI 釐清需求：詢問購買金額
        ↓
AI 分析：根據三種資料判斷時機
        ↓
AI 提案：說明原因、建議金額
        ↓
使用者確認
        ↓
MAX Skill 執行下單
        ↓
下單結果即時反映在 K 線圖上
```

#### 買入條件

**手動買入（使用者主動發起，不符合條件時 AI 警示）**

| 條件 | 說明 |
| --- | --- |
| 恐懼貪婪指數 < 55 | 市場還沒過熱 |
| 短期下降趨勢不明顯 | 7 天移動平均沒有明顯下跌 |
| 使用者在類似條件下勝率 > 50% | 從 CSV 歷史紀錄計算 |

**自動買入提案（符合條件時 AI 主動跳出）**

| 條件 | 說明 |
| --- | --- |
| 恐懼貪婪指數 < 40 | 市場偏恐慌，歷史上是買入好時機 |
| 短期上升趨勢 | 今天價格 > 7 天移動平均 |
| 使用者在類似條件下勝率 > 50% | 從 CSV 歷史紀錄計算 |
| 使用者偏好這種貨幣 | 從 CSV 交易頻率判斷 |

#### 賣出條件

**手動賣出（使用者主動發起，不符合條件時 AI 警示）**

| 條件 | 說明 |
| --- | --- |
| 恐懼貪婪指數 > 45 | 市場開始偏貪婪 |
| 短期上升趨勢不明顯 | 沒有明顯繼續上漲空間 |
| 使用者在類似條件下勝率 > 50% | 從 CSV 歷史紀錄計算 |

**自動賣出提案（符合條件時 AI 主動跳出）**

| 條件 | 說明 |
| --- | --- |
| 恐懼貪婪指數 > 70 | 市場極度貪婪，歷史上是賣出好時機 |
| 短期下降趨勢或已達高點 | 今天價格 < 7 天移動平均 |
| 使用者在類似條件下勝率 > 50% | 從 CSV 歷史紀錄計算 |
| 使用者目前持有這個幣 | 從 CSV 持倉計算 |

#### 不觸發自動提案的情況

| 情況 | 原因 |
| --- | --- |
| 使用者手動關閉功能 | 使用者設定 |
| 買入賣出條件都不滿足 | 市場時機不對 |
| 該幣種不在使用者交易過的清單 | 不符合使用者偏好 |

#### AI 回應 JSON 格式

**有投資建議時：**

```json
{
  "message": "根據你的交易習慣...",
  "investment_suggestion": {
    "action": "buy",
    "currency": "ETH"
  }
}
```

**只有對話時：**

```json
{
  "message": "根據目前市場狀況..."
}
```

> ⚠️ 重要原則：所有涉及金額的操作都必須經過使用者明確確認，AI 不會自動執行交易。
>

## 四、API 文件

### 前後端溝通一覽

| 路徑 | 方法 | 用途 |
| --- | --- | --- |
| `/init` | GET | 使用者進入，確認是否需要上傳 CSV |
| `/upload_csv` | POST | 上傳 CSV 並觸發人格分析 |
| `/candlestick_chart` | GET | 取得 K 線圖資料 |
| `/ai_chat` | POST | 使用者與 AI 對話 |
| `/allow_trade` | POST | 使用者確認下單 |

### 各 API 詳細定義

#### GET /init

```
輸入：無
輸出（需要上傳 CSV）：
{
  "status": "need_csv"
}
輸出（已有資料）：
{
  "status": "ready",
  "currencies": ["BTC", "ETH", "SOL", "DOGE"]
}
```

#### POST /upload_csv

```
輸入：
{
  "csv": "DATA"
}
輸出：
{
  "status": "ready",
  "currencies": ["BTC", "ETH", "SOL", "DOGE"]
}
```

#### GET /candlestick_chart

```
輸入：網址參數
  ?currency=BTC&start=time&end=time
輸出：
{
  "status": "ready",
  "candlestick_chart": "Data"
}
```

#### POST /ai_chat

```
輸入：
{
  "message": "Data"
}
輸出（有投資建議）：
{
  "status": "ready",
  "message": "Data",
  "investment_suggestion": {
    "currency": "BTC",
    "action": "sell",
    "amount": 10
  }
}
輸出（只有對話）：
{
  "status": "ready",
  "message": "Data",
  "investment_suggestion": null
}
```

#### POST /allow_trade

```
輸入：
{
  "currency": "BTC",
  "action": "sell",
  "amount": 10
}
輸出：
{
  "status": "success"
}
```

## API 流程圖

### GET /init

```
收到前端請求
↓
去 S3 查有沒有人格資料
↓
有人格資料？
├── 是 → 回傳 status: ready + 幣種清單 → 結束
└── 否 → 回傳 status: need_csv → 結束
```

---

### POST /upload_csv

```
收到前端的 CSV
↓
CSV 格式正確？
├── 否 → 回傳錯誤，要求重新上傳 → 結束
└── 是 ↓
將 CSV 存入 S3
↓
通知薛宇宏開始分析
↓
薛宇宏有回應？
├── 否 → 重試最多 3 次
│         超過 3 次 → 回傳錯誤給前端 → 結束
└── 是 ↓
將人格分析結果存入 S3
↓
回傳 status: ready + 幣種清單給前端
↓
結束
```

---

### GET /candlestick_chart

```
收到前端請求（幣種 + 時間範圍）
↓
同時做兩件事：
  1. 呼叫 MAX API 取得 K 線資料
  2. 查詢 S3 的 CSV 取得該幣種的買賣紀錄
↓
MAX API 有回應？
├── 否 → 重試最多 3 次
│         超過 3 次 → 回傳錯誤給前端 → 結束
└── 是 ↓
合併 K 線資料 + 買賣紀錄
↓
回傳給前端
↓
結束
```

---

### POST /ai_chat

```
收到前端的使用者 prompt
↓
將 prompt 丟給薛宇宏（第一次）
↓
薛宇宏回傳需要哪些 API 資料
↓
趙文睿抓取對應 API 資料：
  - MAX API（即時行情）
  - CoinMarketCap（恐懼貪婪指數）
  - S3（使用者 CSV 紀錄）
↓
至少一個 API 有回應？
├── 否 → 重試最多 3 次
│         超過 3 次 → 回傳錯誤給前端 → 結束
└── 是 ↓
將可用資料再次丟給薛宇宏（第二次）
↓
薛宇宏有回應？
├── 否 → 重試最多 3 次
│         超過 3 次 → 回傳錯誤給前端 → 結束
└── 是 ↓
將回覆紀錄到 S3（供之後的 ai_chat 使用）
↓
回傳 AI 回覆給前端
↓
結束
```

---

### POST /allow_trade

```
收到前端的交易資料（幣種、買/賣、數量）
↓
呼叫 MAX Skill 執行下單
↓
下單成功？
├── 否 → 判斷失敗原因
│         ├── API 失效 → 重試最多 3 次，失敗回傳錯誤 → 結束
│         └── 餘額不足 → 回傳「餘額不足」給前端 → 結束
└── 是 ↓
將這筆交易寫回 S3 的 CSV
↓
回傳成功訊息給前端
↓
結束
```
